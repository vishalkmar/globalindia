# Phase 17 — SQL injection and other injection flaws

Audience: the developer or auditor who maintains the site. Date: 22 November 2026.

## Injection types considered

| Type | How it would arrive | Where it is stopped |
|---|---|---|
| Classic SQL injection | `' OR 1=1--` in a search box or form | Prisma sends every value as a bound parameter; no SQL is built from strings |
| Blind / boolean SQLi | `' AND 1=1` vs `' AND 1=2` to read data by differences | Same; payload is just text that matches nothing |
| Time-based SQLi | `pg_sleep(5)` | Same; test checks every payload answers in under 3 s |
| Second-order SQLi | stored text later used in a query | No query ever re-uses stored text as SQL; raw queries use `Prisma.sql` with parameters |
| ORM operator injection | `{"slug": {"not": ""}}` instead of a string | Every API body goes through a strict Zod schema: objects where strings are expected are refused (400) |
| JSON filter injection | crafted `where`/`orderBy` keys in the query string | List endpoints build `where`/`orderBy` from an allow-list (`parseListQuery`); unknown keys are ignored, bad values are 400 |
| LIKE wildcard abuse | `%` or `_` in a search to match everything | **Found and fixed in this phase**: `%`, `_` and `\` are escaped before `contains` (`likeTerm()` in `lib/admin/listQuery.js`) |
| Header injection | CR/LF in an email subject or name | `lib/brevo.js` strips CR/LF from subjects, names and addresses |
| Log injection | newlines in user input to forge log lines | `lib/logger.js` strips CR/LF and redacts secret-looking keys |
| Command injection | user data reaching a shell | No `child_process`, `eval`, `new Function` or user-controlled `import()` anywhere in `src/` |
| Template injection | user text evaluated as a template | No server-side template engine; React escapes output; emails escape every value with `esc()` |
| LDAP-style / XPath | n/a | Not used by the site |
| Prototype pollution | `__proto__`, `constructor`, `prototype` keys | `readJson()` rejects them while parsing (400) |
| Path traversal | `../` in a media file name | Media ids are matched against a strict pattern before any file path is built |
| CSV / formula injection | `=HYPERLINK(...)` in an exported cell | Exports prefix `= + - @` cells with an apostrophe (`lib/csv.js`) |
| ReDoS | input crafted to make a regex take forever | All validation regexes are linear (no nested quantifiers); a test runs them on 50,000-character inputs |

## Raw SQL in the code base

| File | Query | Why it is safe |
|---|---|---|
| `src/lib/media/service.js` | `LIKE ${pattern}` over JSON columns to find where a file is used | `Prisma.sql` template (bound parameter); the id is a validated cuid, so it contains no wildcards |
| `src/app/api/health/route.js` | `SELECT 1` | No input |

## Database roles (todos 12-13)

The application must not connect as the database owner. On Neon:

```sql
-- run as the owner (done 22 Nov 2026 on database "globalindia"; re-running rotates the password)
CREATE ROLE gi_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION NOBYPASSRLS PASSWORD '<random>';
ALTER ROLE gi_app CONNECTION LIMIT 60;
ALTER ROLE gi_app SET statement_timeout = '15s';
REVOKE ALL ON DATABASE globalindia FROM PUBLIC;
GRANT CONNECT ON DATABASE globalindia TO gi_app;
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public TO gi_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO gi_app;
REVOKE ALL ON TABLE public."_prisma_migrations" FROM gi_app;
GRANT USAGE, SELECT, UPDATE ON ALL SEQUENCES IN SCHEMA public TO gi_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO gi_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT, UPDATE ON SEQUENCES TO gi_app;
```

- `DATABASE_URL` (used by the running site) connects as `gi_app` (pooled): it can read and write rows but
  cannot create, alter or drop tables, roles or extensions, and cannot read `_prisma_migrations`.
- `DIRECT_URL` (used only by `prisma migrate deploy` during the build) connects as the owner role.
- Default privileges are set for the owner role, so tables added by later migrations are granted to
  `gi_app` automatically.
- Status: **done 22 Nov 2026.** Verified as `gi_app`: row update allowed; `CREATE TABLE`, `DROP TABLE`,
  `CREATE ROLE` and reading `_prisma_migrations` all refused. The URLs live only in the git-ignored
  `.env.neon` (`APP_DATABASE_URL` for the site, owner URL for `DIRECT_URL`) and in Vercel's env settings.

## Tests

`tests/unit/injection.test.js` sends sqlmap-style payloads (classic, blind, time-based, stacked, comment
and encoding tricks) to public search, admin lists and login, plus operator injection, prototype
pollution, oversized bodies, header and log injection, path traversal and ReDoS cases.
