# Phase 29 — UI attack-surface audit

Audience: the developer or auditor who maintains the site. Date: 23 November 2026.

| # | Check | Result | Evidence |
|---|---|---|---|
| 01 | Clickjacking | Pages cannot be framed (`frame-ancestors 'none'`, `X-Frame-Options: DENY`); a page on another origin that frames the admin login gets nothing | `ui-surface.spec.mjs`, `cors.spec.mjs` |
| 02 | Open redirect (`?next=`) | Only same-site `/admin…` paths are followed; full URLs, `//host`, backslashes, encoded tricks, control characters and the auth pages themselves fall back to `/admin` | `safeNext`, `ui-surface.test.js` |
| 03 | Tabnabbing | Every `target="_blank"` link has `rel="noopener noreferrer"`; `Button` adds it for internal links too | `ui-surface.test.js` (scans all source) |
| 04 | Autocomplete | `username` + `current-password` on sign-in, `one-time-code` on codes, `new-password` on new passwords, `off` on recovery codes | `ui-surface.test.js` |
| 05 | Sensitive data in page source / RSC | No password hashes, token versions, code hashes, secrets or connection strings in HTML or RSC payloads of public and admin pages | `ui-surface.spec.mjs` |
| 06 | Error pages | 404 and error pages show plain text only; APIs answer generic messages; no stack, framework or ORM names | `ui-surface.spec.mjs`, `route()` |
| 07 | Admin links from the public site | None (no `/admin` href in any public component) | `ui-surface.test.js` |
| 08 | OTP handling | Codes can be pasted (one input, digits only); no request URL during sign-in contains the code | `ui-surface.spec.mjs` |
| 09 | File previews | PDFs open from Cloudinary in a new tab (never inline in the admin); email previews use a sandboxed iframe without `allow-scripts`; SVG uploads are refused | `ui-surface.test.js`, Phase 19 |
| 10 | Rich text | Sanitised on save and render with an allow-list; payload list incl. mutation XSS | `xss.test.js` |
| 11 | Cookie banner | Analytics scripts load only after "Accept analytics"; "Necessary only" is the default | `site-layout.spec.mjs` |
| 12 | Third-party scripts | Only Turnstile (forms) and, after consent, GA4/Clarity; all Next scripts carry SRI hashes; third-party scripts that change often cannot carry SRI, so CSP limits them to their exact hosts | `next.config.mjs`, `csp.js` |
| 13 | Map embed | Google Maps iframe only after "Show map" | `ui-surface.spec.mjs` |
| 14 | Mixed content | No `http://` resources in the HTML; `upgrade-insecure-requests` in production CSP | `ui-surface.spec.mjs` |
| 15 | HTTPS + HSTS | `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` on every response; HTTP→HTTPS by Vercel/Cloudflare ("Always use HTTPS"). Submit to hstspreload.org once the final domain is live | `ui-surface.spec.mjs` |
| 16 | Lockout messaging | Wrong password, unknown email and locked account all answer `401 Invalid email or password.`; the owner learns of the lockout by email | `ui-surface.spec.mjs`, `login.test.js` |
| 17 | Session expiry | An expired session sends the admin to `/admin/login?next=<page>` (validated) and back after sign-in; idle sign-out explains why | `adminFetch`, `IdleGuard` |
| 18 | Back after logout | Admin pages are `Cache-Control: private, no-store`; going back after sign-out lands on the login page with no data | `ui-surface.spec.mjs` |
| 19 | Browser storage | After sign-in: nothing token-like in localStorage, sessionStorage or script-readable cookies (all auth cookies are HttpOnly) | `ui-surface.spec.mjs`, `no-token-storage.test.js` |
