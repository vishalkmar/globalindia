# Phase 24 — Secrets, logging and error hygiene

Audience: the developer or auditor who maintains the site. Date: 22 November 2026.

## Secret inventory and owners (todo 18)

Owner = who creates and rotates it. "Site owner" means the business owner's account on that service.
Every secret lives only in git-ignored `.env.*` files locally and in Vercel environment variables;
none is ever committed or sent to the browser.

| Variable | What it protects | Owner | Rotate |
|---|---|---|---|
| `DATABASE_URL` | App connection as `gi_app` (rows only) | Site owner (Neon) | Reset `gi_app` password in Neon, update Vercel |
| `DIRECT_URL` | Owner connection, used only for migrations | Site owner (Neon) | Reset `neondb_owner` password in Neon |
| `JWT_ACCESS_SECRET` (+ `_PREVIOUS`, `JWT_ACCESS_KID`) | Admin access tokens | Developer | With kid, no sign-outs (docs/security/23.md) |
| `REFRESH_PEPPER` | Stored refresh-token hashes | Developer | Ends every session |
| `OTP_PEPPER` | Stored sign-in code hashes; CSRF tokens | Developer | Voids open codes and form tokens |
| `MFA_PENDING_SECRET` | The short ticket between password and second factor | Developer | Voids sign-ins in progress |
| `TOTP_ENC_KEY` | Encrypted authenticator secrets | Developer | Needs re-encryption or re-enrolment |
| `IP_HASH_SALT` | Hashed IPs and emails in logs and limits | Developer | Old hashes stop matching (harmless) |
| `CLOUDINARY_API_SECRET`, `CLOUDINARY_WEBHOOK_SECRET` | Signed uploads, webhooks | Site owner (Cloudinary) | Regenerate in Cloudinary |
| `BREVO_API_KEY`, `BREVO_WEBHOOK_SECRET` | Sending email, webhooks | Site owner (Brevo) | Regenerate in Brevo |
| `UPSTASH_REDIS_REST_TOKEN` | Rate-limit store | Developer (Upstash) | Regenerate in Upstash |
| `TURNSTILE_SECRET` | Bot checks on forms | Site owner (Cloudflare) | Rotate in Turnstile settings |
| `CRON_SECRET` | The daily purge endpoint | Developer | Any time |
| `SEED_ADMIN_PASSWORD` | First admin, local seed only | Developer | Not set in production |

Public by design (`NEXT_PUBLIC_`): `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`. A test fails
if any other `NEXT_PUBLIC_` name appears.

## Keeping secrets out of code and bundles (todos 02–09)

- Every module that reads a secret starts with `import "server-only"`, so importing it from a client
  component fails the build. A test checks this for all of `src/`.
- Cloudinary signing and Brevo calls happen only in route handlers and server libraries.
- `productionBrowserSourceMaps: false`; `/.env*`, `/.git/*` and `*.map` answer 404 from the proxy.
- `npm run scan:bundle` after a build scans `.next/static` for known key formats, for the real values of
  local secrets, and for the names of server-only variables.
- `npm run scan:secrets` scans the whole git history. Run on 22 Nov 2026: **nothing found**.
- Pre-commit hook (`.githooks/pre-commit`, installed by `npm install`) refuses commits with secrets or
  `.env` files. CI (`.github/workflows/security.yml`) runs gitleaks and the same scanner on every push.

## Logging (todos 11–16)

- `src/lib/logger.js` writes one JSON line per event and replaces any key that looks like a password,
  token, code, cookie, authorization header, hash or signature with `[redacted]`, at any depth; CR/LF are
  stripped.
- IPs are stored and logged only as HMACs (`hashIp`); rate-limit logs carry the limit name only.
- Auth routes never log request bodies; error responses are generic and 500s never carry a stack.
- `console.log` / `console.debug` are removed from production builds (`compiler.removeConsole`); the
  logger's error / warn / info output is kept. A test fails on any `console.log` in `src/`.

### Retention

| Data | Kept | How |
|---|---|---|
| Runtime logs (Vercel / log drain) | 30 days | Hosting dashboard setting |
| Sign-in codes, reset links, email-change requests, expired sessions | 30 days after they stop working | Daily cron (`src/lib/retention.js`) |
| Audit log | 365 days | Same cron |
| Enquiries, newsletter subscribers | Until deleted by an admin (business records) | Admin |
