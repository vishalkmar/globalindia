# Phase 26 — Webhook signatures and SSRF

Audience: the developer or auditor who maintains the site. Date: 23 November 2026.

## Incoming webhooks

| Webhook | What it does | Checks |
|---|---|---|
| `POST /api/webhooks/brevo` | Unsubscribe, hard bounce, spam complaint, blocked or invalid address → newsletter subscriber set to `UNSUBSCRIBED` | `Authorization: Bearer <BREVO_WEBHOOK_SECRET>` (constant-time); sender IP in Brevo's ranges (`1.179.112.0/20`, `172.246.240.0/20`, overridable with `BREVO_WEBHOOK_IPS`; checked in production); `ts_event` within 5 minutes |
| `POST /api/webhooks/cloudinary` | A file deleted in the Cloudinary console → its media entry goes to the trash | `X-Cld-Signature` = SHA-1 or SHA-256 of raw body + `X-Cld-Timestamp` + `CLOUDINARY_API_SECRET` (constant-time); timestamp within 5 minutes |

Both:

- verify against the **raw body** (read once, capped at 64 KB) before parsing it;
- store each event id (`WebhookEvent`, unique per provider) and answer a repeat with
  `{ ok: true, duplicate: true }` without acting again; ids are purged after 30 days by the retention cron;
- are rate limited (120 / min per IP, plus the global API limit) and answer every failed check with the
  same `401 Not accepted.` (the reason is only in the server log);
- are not covered by CSRF or the admin session (they are machine-to-machine) and act only on ids the site
  created itself (`gi_<32 hex>` media ids; existing subscriber emails).

Setup (owner action): in Brevo → Transactional/Marketing → Webhooks add the URL with "Authentication:
Bearer token" = `BREVO_WEBHOOK_SECRET`; in Cloudinary → Settings → Webhook notifications add the URL.
`CLOUDINARY_WEBHOOK_SECRET` from the env template is not needed (Cloudinary signs with the API secret).

## Outgoing requests (SSRF)

Only one feature fetches a URL given by a person: **Media → Add from link** (`/api/admin/media/from-url`).
There are no link previews, no image proxy (Next's optimiser is off; Cloudinary transforms images) and
no outgoing webhooks. Server-side fetches to fixed hosts (Brevo, Cloudinary, Turnstile, HIBP, Upstash) use
hard-coded https URLs.

`safeFetch` (`src/lib/security/ssrf.js`):

- `https:` only on port 443, no credentials in the URL (`file:`, `gopher:`, `ftp:`, `http:`, `data:` refused);
- the hostname is resolved and **every** answer checked; private, loopback, link-local, CGNAT, multicast,
  reserved and the cloud metadata address `169.254.169.254` are refused; the connection uses the checked
  address, so DNS rebinding between check and connect does not work;
- at most 2 redirects, each re-checked the same way;
- 5-second timeout, 10 MB cap enforced while streaming, `Content-Type` must be on the allow-list
  (images or PDF, by what is being added).

**Host header (CVE-2024-34351 lesson):** the site has no Server Actions, and absolute URLs in emails and
redirects that leave the site are built from `NEXT_PUBLIC_SITE_URL`, never from the request's `Host`.
`next.config.mjs` limits Server Action origins to the site host if one is ever added.

**Images:** `images.loader` is custom (Cloudinary URLs), so there is no `/_next/image` endpoint that
could be used to fetch arbitrary hosts; `remotePatterns` is therefore not needed.

## Tests

`tests/unit/webhooks.test.js` (forged, tampered, stale and replayed webhooks; real events act once;
blocked schemes) and the SSRF cases in `tests/unit/media.test.js` (private, loopback, link-local,
metadata and IPv4-mapped addresses; unsafe URL shapes; hostnames whose DNS answer is private, i.e.
rebinding and metadata). Redirect re-checks reuse the same `assertSafeUrl` + resolve step as the first
request (code review; an end-to-end redirect test needs a local https server and is not automated).
