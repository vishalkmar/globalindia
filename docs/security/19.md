# Phase 19 — Input validation and file upload safety

Audience: the developer or auditor who maintains the site. Date: 22 November 2026.

## Validation

| Rule | Where |
|---|---|
| Every JSON body goes through `readJson(req, schema)`: `Content-Type: application/json` (415), size cap (413, 16 KB default, larger only where needed), prototype-pollution keys refused, then a Zod schema | `src/lib/http.js` |
| Server schemas are `z.strictObject` (unknown keys are an error, not silently kept) | `src/lib/validation/*`, `src/lib/settings/schemas.js`, `src/lib/sections/*` |
| Every string has a maximum length; free text refuses `<` and `>` | same |
| Formats: email, Indian/international phone, https URL, site path, slug, CAS number with check digit, GSTIN, PIN, cuid ids | same |
| Numbers have ranges (upload MB, years, team size, order) | same |
| Route params (`[id]`) are checked against the cuid pattern before any query; query strings go through allow-lists (`parseListQuery`) | every `[id]` route, `src/lib/admin/listQuery.js` |
| Client checks are for speed only: the server runs the same schema again | forms import the server schemas |
| Rich text is sanitised on save and again on render with an allow-list (no script, style, iframe, svg, event handlers, style attributes; links http/https/mailto/tel only) | `src/lib/security/sanitize.js` (sanitize-html) |
| Errors are generic; field messages only for the caller's own input; 500s never include a stack or internal names | `route()` in `src/lib/http.js` |

The only non-JSON body is the development-only local upload (multipart), which checks a signed upload
intent, the declared size and then the bytes themselves; it answers 404 in production.

## File uploads

| Control | Implementation |
|---|---|
| Allowed types | JPG, PNG, WebP, AVIF, PDF only; Settings can switch formats off but never add others |
| Real type check | Magic bytes (`src/lib/media/fileType.js`); the extension and browser MIME are not trusted |
| SVG / HTML / XML | Refused (markup sniffing before type detection) |
| PDF active content | Refused when it contains JavaScript, OpenAction/AA, Launch, EmbeddedFile, RichMedia or XFA, including inside compressed streams |
| Size | Server-side caps (5 MB images, 10 MB PDFs, lowerable in Settings) checked at sign time, on the bytes, and in the Cloudinary signed parameters |
| Image dimensions | Max 12,000 px per side (decompression bombs) |
| File names | Random `gi_<32 hex>` public ids; the user's file name is stored only as text for display |
| Re-encoding | Images are delivered through Cloudinary transformations (`f_auto,q_auto`), never the original bytes |
| Rate | 60 files per admin per hour (`upload` limit) |
| Who | Only roles with `media:create`; every upload is audited |
| Upload from URL | SSRF-safe fetch: https only, DNS checked at connect time, private/loopback/link-local/metadata ranges blocked, size and time caps, no redirects into private ranges |

## Fuzzing

`tests/unit/fuzz.test.js` sends 40 seeded random payloads (nested objects, huge numbers, broken JSON,
unicode, control characters, template and SQL strings, prototype keys) to 11 public and admin write
endpoints. None may answer 500 or leak a stack; garbage is never accepted as a success.
