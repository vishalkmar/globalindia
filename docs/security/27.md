# Phase 27 — Dependencies, CDN, WAF and denial of service

Audience: the developer and the site owner (Cloudflare / Vercel steps). Date: 23 November 2026.

## Dependencies (todos 01–06)

- `npm audit` (23 Nov 2026): no advisories in anything the running site loads. Three "high" advisories
  sit in the **Prisma CLI** (`prisma` → `@prisma/config` → `deepmerge-ts` < 8), used only by
  `prisma migrate` / `generate` on our own schema at build time; no user input reaches it. The fix is
  Prisma 7 (breaking); planned as its own upgrade task. The `effect` advisory in the same chain was fixed
  with an npm override (`effect` ^3.22.5).
- `scripts/audit-gate.mjs` fails CI on any high/critical advisory that is not on that written list.
- `.github/dependabot.yml`: weekly npm and GitHub Actions updates (Monday 06:00 IST), grouped.
- `package-lock.json` is committed; CI uses `npm ci` and `npm audit signatures` (registry signatures and
  provenance of every installed package).
- Unused packages removed (`dotenv`). Next.js and React are pinned to exact versions (16.4.6, 19.3.0).

## Cloudflare in front of Vercel (todos 07–11, 13, 14) — owner action once the domain is ready

1. Add the domain to Cloudflare; DNS records for the site **proxied** (orange cloud) to Vercel.
   SSL mode **Full (strict)**; "Always use HTTPS" on; minimum TLS 1.2.
2. Security → WAF → **Managed rules**: Cloudflare Managed Ruleset and **OWASP Core Ruleset** on
   (paranoia level 1, action Block); Bot Fight Mode on.
3. Custom rules:
   - block requests whose user agent is empty or a known scanner (`sqlmap`, `nikto`, `nmap`, `masscan`,
     `zgrab`) — expression `http.user_agent eq "" or http.user_agent contains "sqlmap" or …`;
   - optional: `/admin` and `/api/admin` only from India (`ip.geoip.country ne "IN"` → Managed challenge);
   - the rate-limit rules in `docs/security/22.md`.
4. **DDoS**: HTTP DDoS protection is always on. Runbook below for "Under Attack" mode.
5. **Cache**: Next.js sends `Cache-Control: public, max-age=31536000, immutable` for `/_next/static/*`;
   Cloudflare keeps them at the edge. Add a Cache Rule "Cache everything" for `/_next/static/*` and
   nothing else (never `/admin` or `/api`).
6. **Slow connections**: Cloudflare buffers and times out slow uploads/bodies (Slowloris) before they
   reach Vercel; nothing extra to set.
7. **Origin lock**: Rules → Transform Rules → Modify request header: set `x-origin-lock` to a random
   value (`npm run secrets` style, 32+ chars) on all requests; put the same value in Vercel as
   `ORIGIN_LOCK_SECRET`. From then on, requests that reach Vercel directly get a 404 (cron and
   `/api/health` excepted). In Vercel → Settings → Deployment Protection, keep preview URLs protected.

## Limits inside the app (todo 12, 15)

- JSON bodies 16 KB by default (`readJson`), webhooks 64 KB, uploads go straight to Cloudinary with signed
  size limits; Vercel ends a function after its configured maximum duration.
- Images: no `/_next/image` endpoint (custom loader). Delivery URLs only use the fixed widths
  64–2048 and a few quality steps (`IMAGE_WIDTHS` in `src/lib/media/imageLoader.js`). In Cloudinary →
  Settings → Security turn on **Strict transformations** so only transformations already used by the
  site can be generated.

## Load test (todo 18)

`node scripts/load-public.mjs http://localhost:3000 20 64` against `next start` on the development
laptop (23 Nov 2026): **635 requests/s**, p50 97 ms, p95 128 ms, p99 150 ms, 12,732 requests, 0 errors
across nine public pages. That is the origin alone with no CDN; behind Cloudflare most HTML and every
static file is served from the edge, so 500 rps on public pages has ample margin.

## Monitoring (todo 16)

## Runbooks (todos 10, 17)

### "Under Attack" (traffic flood)

1. Cloudflare → Overview → **Under Attack Mode: On** (every visitor gets a short browser check).
2. Security → Events: find the attacking pattern (path, country, ASN, user agent); add a custom rule to
   block or challenge it; lower the rate-limit thresholds for the targeted path.
3. If the admin is targeted, add the country rule for `/admin` and, if needed, block IPs in
   Settings → Rate limits and blocked IPs.
4. When traffic is normal for 1 hour, switch Under Attack Mode off and keep the new rules for a week.

### Security incident (suspected break-in or data leak)

1. **Contain**: Settings → Maintenance mode on if the public site is affected; disable suspicious admin
   accounts (Users); "Sign out everywhere" for every admin.
2. **Rotate**: secrets that may be exposed, following docs/security/23.md and 24.md (database passwords
   in Neon, API keys in Brevo/Cloudinary/Upstash/Turnstile, JWT key with kid).
3. **Investigate**: Admin → Audit log (filter by user and time), Vercel logs, Cloudflare security events,
   Neon branch from before the incident (point-in-time restore) to compare data.
4. **Recover**: restore data from a Neon branch if needed (docs/operations/backups.md), redeploy a known
   good commit, switch maintenance off.
5. **Notify**: if personal data of customers leaked, the owner informs affected people and, under India's
   DPDP Act 2023, the Data Protection Board as required; keep a written timeline.
6. **Learn**: write what happened and what changes, within a week.
