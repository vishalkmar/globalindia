# Phase 23 — JWT, tokens, OTP and session hygiene

Audience: the developer or auditor who maintains the site. Date: 22 November 2026.

## Rules and where they are enforced

| # | Rule | Where | Test |
|---|---|---|---|
| 01 | Key secrets are at least 64 random bytes (86 base64url chars); `npm run secrets` makes a fresh set, one set per environment (local, preview, production) | `requireSecret` in `src/lib/env.js`, `scripts/gen-secrets.mjs` | `secrets.test.js` |
| 02 | One secret per purpose: `JWT_ACCESS_SECRET`, `REFRESH_PEPPER`, `OTP_PEPPER`, `MFA_PENDING_SECRET`, `IP_HASH_SALT`, `TOTP_ENC_KEY`; the server refuses to start a request path if two share a value | `requireSecret` | `secrets.test.js` |
| 03 | HS256 pinned on verify; `alg:none`, HS512 and RS/HS confusion rejected | `src/lib/auth/jwt.js` | `jwt.test.js` |
| 04 | Tokens are always verified; there is no decode-only helper | `verifyAccessToken` | `jwt.test.js` |
| 05 | `iss`, `aud`, `exp`, `nbf`, `iat`, `jti`, `sub` required and checked | `jwt.js` | `jwt.test.js` |
| 06 | Access token 10 minutes; refresh token 7 days | `ACCESS_TOKEN_TTL_SECONDS`, `REFRESH_TOKEN_TTL_SECONDS` | `secrets.test.js` |
| 07 | Refresh token rotates on every use; reuse of an old one revokes the whole family and emails the owner | `src/lib/auth/session.js` | `session.test.js` |
| 08 | `tokenVersion` (`tv` claim) bumped on password change, reset, role change, disable and "sign out everywhere"; older access tokens stop working at once | `revokeAllForUser`, users and password routes | `session.test.js`, `reset.test.js` |
| 09 | A password reset revokes every session | `/api/auth/reset/confirm` | `reset.test.js` |
| 10 | Reset links: single use (atomic), 15 minutes, stored hashed | `/api/auth/reset/*` | `reset.test.js` |
| 11 | Email change: current password, then a code to the old address, then a link to the new one | `/api/auth/email-change/*` | `token-hygiene.test.js` |
| 12 | OTP never in a response, a log line or a URL | `otp.js`, logger redaction | `token-hygiene.test.js`, `mfa.test.js` (only a hash is stored) |
| 13 | OTP: 5 minutes, single use, HMAC-hashed with `OTP_PEPPER`, burnt after 5 wrong tries | `src/lib/auth/otp.js` | `mfa.test.js` |
| 14 | Same answer and timing for unknown emails (login, reset, newsletter) | `checkPassword` (dummy argon2), reset request | `login.test.js`, `reset.test.js` |
| 15 | No token in `localStorage`/`sessionStorage`/`document.cookie`; the CSRF token lives only in memory | client code | `no-token-storage.test.js` |

## Rotating secrets (todo 17)

**Access-token key (no one is signed out):**

1. Generate a new value: `npm run secrets` (copy only `JWT_ACCESS_SECRET`).
2. In Vercel set `JWT_ACCESS_SECRET_PREVIOUS` = the current value and `JWT_ACCESS_KID_PREVIOUS` = the
   current kid (e.g. `k1`).
3. Set `JWT_ACCESS_SECRET` = the new value and `JWT_ACCESS_KID` = a new kid (e.g. `k2`). Redeploy.
4. New tokens carry `kid: k2`; tokens signed with `k1` keep working until they expire (10 minutes).
5. After 15 minutes remove the two `_PREVIOUS` variables and redeploy.

**Refresh pepper, OTP pepper, MFA ticket secret:** these hash stored values, so changing one ends
every session (refresh), voids open codes (OTP) or open sign-in steps (MFA ticket). Change them at a
quiet time; admins simply sign in again.

**TOTP encryption key:** authenticator secrets are encrypted with it. Do not change it without a
re-encryption script; if it ever leaks, have every admin re-enrol their authenticator app.

**After any suspected leak:** rotate the affected secret as above, then use "Sign out everywhere" for
each admin (or bump `tokenVersion` for all), and check the audit log.
