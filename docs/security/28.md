# Phase 28 — Anti-bot, anti-scraping and historic CVEs

Audience: the developer and the site owner. Date: 23 November 2026.

## The honest limit (todo 01)

Anything a browser can show, a person can save or copy. The aim is not to make the catalogue secret
(it is a sales website) but to make **bulk** copying slow, noisy and expensive, and to keep the few
private things (batch documents, admin, enquiry data) out of reach.

## What the site does

| Measure | How |
|---|---|
| Bot management (02, 03, 05, 06) | Cloudflare Bot Fight Mode / Super Bot Fight Mode, Managed Challenge for low bot scores and for more than 120 product-page views per minute from one IP, block of known scraper user agents and hosting ASNs on `/products/*` (owner action, rules in docs/security/27.md) |
| Forms (04) | Turnstile + honeypot + time-to-submit on enquiry and newsletter forms. Search and downloads use rate limits instead of a challenge (a widget on every search would hurt real buyers); Cloudflare's Managed Challenge covers abusive volumes |
| No open catalogue API (07) | Public JSON endpoints are search (8 products, 5 categories per query, 60/min per IP, same-origin fetch only), enquiry, newsletter, basket and consent. There is no list-all endpoint; admin APIs need a session, CSRF token and permission |
| Documents (08) | Pages link to `/d/<id>`. That route answers only for PDFs that are a **public** product document or listed in a visible Downloads section of a published page, refuses links from other websites (`Sec-Fetch-Site: cross-site`), allows 30 downloads per 10 minutes per IP, and redirects to a **Cloudinary download link that expires after 10 minutes** (signed with the API secret). Batch COAs are never served (they are sent with quotes). In Cloudinary → Settings → Security, keep PDF under "Restricted media types" so the plain public URL does not work |
| Watermark (09) | Owner choice (needs the final logo). Steps: upload the logo to Cloudinary as `global-india/watermark`, then add an incoming transformation `l_global-india:watermark,o_25,g_south_east,w_0.18,fl_relative/fl_layer_apply` to product image uploads, or a named transformation used by the loader |
| AI crawlers (10) | Settings → SEO → "Ask AI crawlers not to read the site" adds GPTBot, CCBot, ClaudeBot, Google-Extended, PerplexityBot, Bytespider and others to `robots.txt` (`src/app/robots.js`). Off by default until the owner decides. `/admin`, `/api/` and `/d/` are always disallowed |

## Historic CVEs (11–18)

| CVE / lesson | Status here |
|---|---|
| CVE-2025-29927 — middleware bypass with `x-middleware-subrequest` | Next 16.4.6 (fixed); the proxy also deletes the header; the proxy is not the auth layer (every handler checks) |
| CVE-2025-55182 / CVE-2025-66478 — React Server Components RCE | React 19.3.0 and Next 16.4.6 (fixed in React 19.2.1 / Next 16.0.7); a test fails if older versions come back |
| CVE-2024-34351 — Server Actions SSRF via Host header | No Server Actions; external URLs built from `NEXT_PUBLIC_SITE_URL`; `allowedOrigins` set |
| CVE-2024-46982 — cache poisoning of dynamic routes | Fixed versions; admin and API responses send `Cache-Control: private, no-store` |
| jsonwebtoken CVE-2022-23529/23539/23540/23541 | `jsonwebtoken` not used; `jose` with the algorithm pinned to HS256 and key ids |
| Prototype pollution (lodash, minimist) | Not used by the site; only lint tools pull patched `lodash.merge` 4.6.2 and `minimist` 1.2.8; request bodies with `__proto__`/`constructor` keys are refused |
| Log4Shell lesson | The logger writes JSON only, never evaluates or formats input; email templates escape every value |
| Supply chain (event-stream, xz) | Lockfile + `npm ci`, `npm audit signatures`, few dependencies, Dependabot, audit gate in CI |

## Keeping up (19)

Monthly (first Monday, with the Dependabot pull requests): read the security advisories for Next.js
(github.com/vercel/next.js/security), React, Prisma and jose, run `node scripts/audit-gate.mjs`, and
update this table.
